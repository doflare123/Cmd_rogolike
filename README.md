# CmdRoguelike

Игра открывается главным меню. Доступны три независимых прохождения, настройки, информация о создателе, энциклопедия встреченных предметов и выход. У каждого прохождения своя база, герой, хранилище и открытия.

База — постоянная ASCII-карта со свободными местами под вспомогательные объекты. WASD/стрелки перемещают героя; E рядом с сундуком открывает запасы, рядом с костром/целителем восстанавливает ресурсы, рядом с воротами отправляет в экспедицию. I/F открывает подготовку, C — запасы, B — расстановку. В расстановке: WASD — курсор, Tab — сундук/костёр/верстак/целитель, Enter — поставить или выбрать объект для переноса, Del — убрать, Esc — закончить. Ворота и последний сундук остаются; нельзя перекрыть связность базы. Верстак пока резервирует место под будущий крафт. Все сундуки используют одно хранилище на 64 слота.

Перед первой экспедицией возьмите в запасах огненный факел; там же есть лечебные зелья. Подготовьте кольцо силы, доспех, факел и щит, затем отдохните у костра и отправляйтесь. Мудрый дуб появляется в новом подземелье после некоторого исследования с защитой от неудачной серии поиска. Он имеет крепкую физическую броню и слабость к огню, защищается, готовит удар и сильно атакует каждый третий раунд. Победа открывает портал O на его бывшей клетке. Соберите награду и войдите в портал: герой возвращается с экипировкой, добычей и текущими ресурсами, а следующая ступень усиливает дуба.

Полные сохранения доступны только на базе: F5, перед походом, после возвращения и при уходе в главное меню. При запуске из проекта они находятся в `.godot/campaigns/campaign-1.json` ... `campaign-3.json`, в экспорте — `user://campaigns`. Выход из экспедиции вне боя возвращает последнее сохранение на базе и не убивает героя; несохранённая карта и добыча теряются. Смерть или выход во время незавершённого боя теряет героя и взятые вещи; запасы базы остаются. Закрытие окна/уход в меню во время экспедиции требует подтверждения в игре. Служебный файл `.combat` фиксирует только незавершённый бой, а не состояние экспедиции.

Энциклопедия показывает только встреченные типы предметов, их требования, бонусы и карты. A/D переключает прохождение. Создатель: участник doflare, Telegram https://t.me/necrodwarfs.

Прототип бесконечного ASCII-рогалика на Godot 4.6 и C#.

Подробное целевое видение персонажа, карточного боя, скрытых секций комнат, предметов, повторно усложняющихся боссов, базы, метапрогрессии и адаптивного ИИ находится в [`docs/CHARACTER_COMBAT_VISION.md`](docs/CHARACTER_COMBAT_VISION.md). Реализованы характеристики, предметы с редкостью и аффиксами, экипировка, раскрытие секций, первый карточный бой и награды с рулетками и помощью расходниками; реализован первый босс и возвращение на базу, расширенная метапрогрессия остаётся проектным направлением.

## Запуск

Откройте проект в Godot и нажмите `F5`.

На базе I открывает терминальный экран подготовки: рюкзак на 12 слотов слева, все слоты экипировки справа, описание выбранного предмета снизу. Моноширинная сетка с ASCII-рамками масштабируется под окно без общей прокрутки. Раса — `null`, без бонусов. Выберите кольцо силы, затем учебный меч и доспех. Предметы и герой сохраняются при переходе на карту. Тестовые перья и аффиксные образцы оставлены только в изолированной подготовке smoke-тестов. Числа предметов пока тестовые.

Управление подготовкой: `W/S` или вверх/вниз — выбор; `A/D`, влево/вправо или `Tab` — панель; `Enter/E` — надеть или снять; `Q` — выбрать слот для кольца; `F` — начать экспедицию. В экспедиции экипировка доступна только для просмотра, но расходники можно использовать через `Enter/E` между боями; `I/Esc` закрывают инвентарь. Удерживайте `Alt` для подробностей выбранного предмета и источников карт.

Снаряжение меняется только при подготовке. Требования проверяются без собственных бонусов при первом надевании; активный предмет может поддерживать себя. При потере требований он остаётся в слоте как `Dormant` и не даёт бонусов до восстановления требований. Изменение максимума HP не лечит.

Активная экипировка добавляет карты к базовой колоде героя. Учебный меч даёт 3 рубящих удара (1 AP, 2 урона), альтернативная булава — 2 сокрушения (2 AP, 4 урона), щит — 1 броню и 2 карты щита (1 AP, блок 200% брони). Меч и булава занимают одну основную руку: для смены сначала снимите текущее оружие. Состав колоды с ценой и эффектом виден в подготовке, источники показываются при удерживании Alt; карты выбранного предмета — в его описании. Это прототипный баланс.

В изолированной подготовке smoke-тестов есть два образца с аффиксами: необычная кираса и редкий щит стража. Указатель `>` отмечает выбор. Обычно видны полное имя, уровень, требования, итоговые бонусы, стоимость и готовые эффекты карт. Удерживание `Alt` дополнительно раскрывает базу, базовые бонусы, префиксы/суффиксы с тирами и диапазонами, источники карт и процент брони при расчёте блока. Это подробности выбранного предмета, а не полный отчёт по источникам характеристик героя. Отпускание `Alt`, потеря фокуса окна, закрытие инвентаря и открытие настроек скрывают подробности; режим не сохраняется и не переключается одиночным нажатием. При открытии инвентаря через `I` уже удерживаемый `Alt` учитывается. Для кирасы сначала выполните требование Силы и освободите корпус; щит можно сразу надеть во вторую руку.

Инвентарь и награда используют одну палитру:

| Редкость | Код | Цвет | Случайная добыча сейчас |
| --- | --- | --- | --- |
| Обычный | `O` | Белый | Да |
| Редкий | `R` | Зелёный | Да |
| Необычный | `N` | Синий | Да |
| Эпический | `E` | Фиолетовый | Пока нет |
| Легендарный | `L` | Жёлтый | Пока нет |
| Уникальный | `U` | Плавный перелив от тёмно-красного к жёлто-оранжевому и обратно за 2 секунды | Пока нет |

Прежняя магическая редкость (`Magic/M`) переименована в необычную (`Uncommon/N`); её лимиты аффиксов сохранены. Цвета сами не меняют силу предмета или вероятности награды. Имя Dormant сохраняет цвет редкости, янтарным выделено состояние. Перелив уникального предмета меняет только оформление, без переброса свойств.

Редкость ограничивает число аффиксов: обычный предмет — без них, необычный — 1–2 с максимумом по одному префиксу и суффиксу, редкий — 3–4 с максимумом по два каждого вида. Лимиты редких предметов настраиваются через `ItemRarityRules`, до трёх каждого вида. Эпическая, легендарная и уникальная редкости поддержаны для заданного контента и оформления, но пока не участвуют в случайной добыче; их правила выпадения и свойств ещё не определены. Редкость сама не умножает характеристики. Тиры T1/T2/T3 открываются на уровнях предмета 1/5/10; среди доступных тиров выбирается случайный. Характеристики и броня имеют диапазоны +1–2 / +3–4 / +5–6, максимумы HP/MP — +2–4 / +5–7 / +8–10. Это временный контент.

Значения аффиксов выбираются один раз отдельным seeded RNG и остаются у экземпляра при надевании, Dormant и входе в бой. Группа аффикса не повторяется; броня доступна только доспехам и щитам. Собственная Сила аффикса не помогает первому надеванию или восстановлению Dormant, но поддерживает уже активный предмет. Карты защиты используют итоговую броню. Образцы подготовки воспроизводимы после `R`; самостоятельный контент уникальных вещей с особыми эффектами, аффиксы AP/карт и сложные эффекты ещё не подключены. Наличие оформления Unique не добавляет такие вещи в игру.

## Награда после боя

После победы `Enter/F` открывает экран награды. Каждая встреча даёт один предмет экипировки; бюджет учитывает количество и сложность врагов, сочетание защитника с громилой и число собственных ходов. Быстрый бой даёт ограниченный бонус, затягивание не улучшает награду. Редкость, уровень и все аффиксы рассчитываются один раз при победе отдельным RNG, до анимаций. Числа и ассортимент пока прототипные.

При остатке HP ≤35% часть бюджета экипировки идёт на зелье здоровья; при MP ≤35% — на зелье маны, если максимум MP больше нуля. На каждый нужный ресурс отводится 12%, всего максимум 24%; бюджет экипировки округляется вверх. Зелья восстанавливают 40% соответствующего максимума с округлением вверх и ограничением до полного ресурса. Победа сама не лечит.

Каждый аффикс раскрывается отдельной рулеткой. `Esc` мгновенно показывает оставшиеся свойства и оставляет экран получения открытым. `F2` открывает настройки, где `Enter/A/D` отключает или включает рулетки; `Esc/F2` возвращает в игру. Настройки ставят бой и раскрытие на паузу. В локальном проекте выбор сохраняется в `.godot/player-settings.cfg`, в экспортированной игре — в пользовательской папке Godot. Анимации не меняют результат награды.

На экране награды `W/S` выбирает предмет или расходник, `Enter/E` забирает его в рюкзак, `F/Space` возвращает на карту, `I` открывает инвентарь. Есть сравнение с надетыми предметами. При полном рюкзаке получение отклоняется целиком, добыча сохраняется. Незабранная награда отмечена `*`, клавиша `G` снова открывает её в той же секции; повторного броска и повторного получения забранных вещей нет. Экипировка в экспедиции остаётся заблокированной.

Забранные предметы сразу исчезают из списка и при повторном открытии не показываются; выбор переходит к оставшимся записям. Если остались только расходники, отображаются только они, без описания и сравнения забранной экипировки. При полном получении экран показывает «Добыча собрана», `Enter/E` ничего не забирают; `F/Space` возвращают к карте. Снимок награды сохраняется, повторное открытие не запускает завершённые рулетки. Для предмета без аффиксов интерфейс не выводит сообщения об их отсутствии и нулевые счётчики свойств; в инвентаре также нет строки «Аффиксы: нет».

Зелья используются через `I`: выберите расходник и нажмите `Enter/E`. Это доступно между боями; полный ресурс не расходует зелье, мёртвого героя оно не воскрешает. Расходники стакаются по 10. Боевые быстрые слоты и длительная регенерация пока не реализованы.

`res://tests/reward_smoke_test.tscn` проверяет расчёт награды, помощь ресурсами, воспроизводимость, отсутствие награды за поражение, атомарность получения, полный рюкзак, сохранение добычи, восстановление HP/MP, независимость RNG мира, последовательные рулетки, пропуск и сохранение настройки. Проверяет также исчезновение забранного сразу и при повторном открытии, экран оставшихся расходников, получение через отфильтрованный список, безопасные `Enter/E` при пустой добыче и отсутствие сообщения о невыпавших аффиксах. С графикой сохраняет `.godot/reward-roulette.png`, `.godot/reward-ui.png`, `.godot/reward-ui-small.png` и `.godot/reward-remaining.png`; боевой UI-тест также проверяет переход к награде, повторный ввод и настройки.

- `WASD` или стрелки — ходить;
- `E` или `Space` — открыть соседнюю дверь;
- попытка войти в `+` также открывает дверь;
- `I` — открыть просмотр инвентаря, `I`/`Esc` — закрыть;
- `G` — открыть оставшуюся добычу текущей секции;
- `F2` — настройки рулеток; `Esc/F2` закрывают настройки;
- `R` — отладочный сброс только в изолированном режиме smoke-тестов;
- `Esc` — выйти.

Обозначения: `@` — игрок, `e` — враг любого из трёх типов, `#` — стена, `+` — закрытая дверь, `/` — открытая дверь, `*` — оставшаяся добыча. Проходимый пол намеренно не рисуется.

Дополнительные проверки: `res://tests/equipment_smoke_test.tscn` и `res://tests/preparation_ui_smoke_test.tscn` запускаются Godot Mono с `--headless --path .`. UI-тест проверяет также нажатие и отпускание Alt через контроллер игры; с графикой сохраняет `.godot/preparation-ui.png` и `.godot/preparation-ui-small.png`.

`res://tests/item_affix_smoke_test.tscn` проверяет 900 seeded комбинаций трёх текущих случайных редкостей и уровней 1/5/10, ограничения редкости/уровня/категорий/групп, независимость экземпляров, Dormant, ресурсы, источники карт и вместимость рюкзака. Дополнительно проверяет скрытие подробностей до Alt и после отпускания, палитру шести редкостей, период перелива Unique, создание заданных Epic/Legendary/Unique и отказ их случайной генерации. С графикой сохраняет `.godot/inventory-default.png`, `.godot/affix-ui.png`, `.godot/affix-ui-small.png` и `.godot/rarity-colors.png`; вещи для снимка палитры существуют только у тестового героя.

## Карточный бой

Вход в секцию с обнаруженными врагами открывает отдельную ASCII-сцену в стиле JRPG. Мир сохраняет позиции, но в бою нет движения и дальности. Двери доступны после победы. Закрытые секции скрывают карту и врагов; открытая дверь раскрывает следующую секцию только после входа на её пол.

Боевая сцена использует 2.5D-проекцию из символов: фронтальная перспектива комнаты с задней и боковыми стенами, трапециевидным полом и силуэтами бойцов, карты с рисунками и толщиной, отдельные стопки колоды и сброса. AP показаны крупной цифрой на отдельной плашке; здоровье с красной полоской, блок, броня, воля и MP собраны в другой панели. Заголовки карт обозначают только действие, стоимость и эффект — номера рядом с углом рамки убраны. Сообщения расположены ниже карт с отдельным зазором.

Силуэт защитника переработан: отчётливые шлем, корпус, ноги и щит с закрытым контуром. Это изменение рисунка в прежнем размере; боевые характеристики, намерения и анимации сохраняются.

Кнопка «Журнал боя» или `L` открывает историю всей текущей встречи: раунд, действие и цель, урон, поглощённый блок, защита, замена карт и результат. `W/S`, стрелки или колесо мыши прокручивают записи; `PgUp/PgDn` — страницы, `Home/End` — начало/конец. `L/Esc` закрывают журнал. Пока он открыт, анимации стоят на паузе и боевые команды недоступны. После встречи история закрывается вместе с боевым экраном.

После входа в занятую секцию карта остаётся видна 0,85 секунды: появляются противники и сообщение об обнаружении. Затем экран плавно затемняется и открывается бой. Розыгрыш и замена сопровождаются полётом карт; удары — выпадами, дрожанием и числами урона; защита — контуром щита. Враги атакуют последовательно, HP и блок на экране меняются в момент попадания. Боевой ввод заблокирован до завершения анимации. Выбранная карта приподнимается, цель подсвечивается. При большом числе врагов W/S переключает видимую группу из трёх силуэтов; действующий враг показывается автоматически. Проекция декоративная и не раскрывает скрытые секции мира.

Порядок участников определяется Willpower каждый раунд. До героя действует не более 30% живых врагов (округление вниз) с большей Волей, остальные — после. Перед подтверждением раунда показаны цель и урон всех намерений.

У героя 3 AP в базе. Они полностью восстанавливаются в начале собственного хода, остаток не переносится. Все атаки требуют карт: базовая колода содержит 6 атак и 4 защиты плюс карты активной экипировки, рука — 5. Атака за 1 AP наносит 1 урон; защита за 1 AP создаёт блок в размере 100% брони. Учебный доспех даёт 2 брони. Блок складывается, поглощает общий урон и исчезает в начале следующего собственного хода, после ранних атак врагов. Dormant не даёт брони и блокирует розыгрыш карт своего предмета; такие карты можно заменить, после восстановления источника они снова работают. Состав колоды фиксируется в начале встречи. Будущие бонусы AP поддерживаются общим движком статов.

В комнатах встречаются три типа: обычный Enemy (3 HP, атака на 1), защитник (4 HP, чередует 2 блока и атаку на 1), громила (5 HP, чередует подготовку без урона и сильный удар на 3). Намерения показывают действие, цель, силу и порядок до подтверждения раунда. Блок защитника поглощает ваши удары и исчезает перед следующим его действием. Подготовку можно пресечь, победив громилу до удара. Типы выбираются воспроизводимо с весами 50/30/20%, отдельно от случайности геометрии. Все обозначаются `e` на карте; в бою различаются именами, силуэтами и намерениями.

- `Enter/E` — подтвердить начало раунда или сыграть карту;
- `A/D` или влево/вправо — выбрать карту;
- `W/S` или вверх/вниз — выбрать противника;
- `Q` — бесплатно заменить карту с добором, раз в два собственных хода;
- `Space` — закончить ход, даже если остались AP;
- `I` — посмотреть инвентарь;
- после победы `Enter/F` — открыть награду, затем `F/Space` — продолжить исследование;
- после поражения `R` — создать нового героя и начать подготовку.

После победы сохраняются герой, вещи и оставшееся здоровье; поверженные враги освобождают клетки. Мудрый дуб и возвращение на базу реализованы; сложный AI, новые фазы и расширенная метапрогрессия остаются будущими этапами. Дополнительные проверки: `res://tests/combat_smoke_test.tscn` и `res://tests/combat_ui_smoke_test.tscn`. Графический UI-тест сохраняет `.godot/combat-ui.png` и `.godot/combat-ui-small.png`.

## Архитектура

Зависимости направлены от внешних слоёв к внутренним:

```text
Presentation → World → Generation
                  ↘      ↓
                 State / Domain / Core
```

### `scripts/Core`

Небольшие общие типы без игровой логики:

- `DungeonTile` — тип клетки;
- `CardinalDirection` — направление и операции `ToOffset`/`Opposite`.

### `scripts/Domain`

Модели предметной области:

- `DungeonRegion` — сгенерированная комната или коридор;
- `DungeonDoor` — внутренняя или внешняя дверь;
- `DoorExpansion` — результат открытия двери;
- `DungeonRegionKind` — тип области.

Сущности находятся в `scripts/Domain/Entities` и образуют расширяемую иерархию:

```text
DungeonEntity
└── Actor
    ├── PlayerCharacter
    └── Enemy
        ├── BasicEnemy
        ├── GuardianEnemy
        └── BruteEnemy
```

`DungeonEntity` — основа для любых объектов на карте. `Actor` композиционно содержит базовые характеристики, производные значения и текущие ресурсы; этим общим стат-движком пользуются и герой, и противники. `PlayerCharacter` представляет единственного управляемого героя, `Enemy` — общие свойства противников, а `BasicEnemy` является первым конкретным типом.

`Domain/Items` хранит определения, неизменяемые результаты генерации `ItemRoll`, экземпляры и инвентарь; `ActorInventory` создаёт получаемые героем экземпляры, `ItemStorage` владеет запасами базы. Передача сохраняет идентичность предмета и меняет его владельца. `Domain/Rewards` отделяет снимок победы и расчёт бюджета от готовой награды. `Domain/Combat` исполняет карты и зафиксированные намерения, а `Domain/Stats` рассчитывает характеристики с источниками модификаторов.

Модели не обрабатывают ввод и ничего не рисуют.

### `scripts/State`

Изолированное изменяемое состояние:

- `DungeonGrid` — разреженное хранилище пола, перегородок и дверей; внешний контур стен вычисляется глобально для всей раскрытой карты;
- `DoorRegistry` — единый реестр дверей;
- `EntityRegistry` — позиции и поиск динамических сущностей; атомарно обновляет объект и позиционный индекс при перемещении;
- `DungeonKnowledge` — известная карта и текущая раскрытая секция, без выдачи скрытых врагов.

Генераторы и фасад мира используют эти хранилища, но не зависят друг от друга циклически.

### `scripts/World`

Публичное API мира:

- `DungeonMap` — фасад мира: регистрирует игрока, выполняет команды движения/дверей, проверяет проход и координирует раскрытие областей.
- `PreparationSession` — герой и воспроизводимые учебные предметы перед экспедицией;
- `RewardCache`/`RewardEntry` — добыча комнаты и признаки получения; UI фильтрует забранное, исходная награда сохраняется. `DungeonMap` проверяет получение по Id, вместимость и использование расходников.

`DungeonMap` координирует ленивое расширение мира, но не строит геометрию самостоятельно.

### `scripts/Generation`

Процедурная генерация разделена по ответственности:

- `DungeonGenerationOptions` — валидируемые параметры генератора;
- `IRandomSource` — абстракция случайности;
- `GodotRandomSource` — seed-зависимая реализация;
- `RegionGenerator` — выбирает тип области и собирает зависимости;
- `RoomGenerator` — форма комнаты и внутренние перегородки;
- `CorridorGenerator` — коридорные области;
- `RegionExitPlanner` — прямые, угловые, Т- и крестовые наборы выходов;
- `RegionDoorBuilder` — общие граничные двери и подходы к ним;
- `RegionGeometry` — низкоуровневая резка пола; итоговый внешний контур строит `DungeonGrid`.
- `EnemyGenerator` — решает, нужно ли заселять созданную комнату, и выбирает свободные позиции;
- `IEnemyFactory`/`EnemyFactory` — создаёт конкретный тип врага независимо от алгоритма размещения.
- `ItemRollGenerator` — выбирает аффиксы и их значения; `CombatRewardGenerator` — генерирует один предмет и помощь ресурсами по готовому бюджету. Случайность наград отделена от геометрии, типов врагов и колоды.

Например, для добавления нового алгоритма комнаты нужно менять `RoomGenerator`, не затрагивая ввод, отрисовку или хранение карты.

### `scripts/Presentation`

Godot-слой:

- `DungeonGame` — корневой узел, преобразующий ввод в игровые команды; позицию персонажа не хранит;
- `AsciiDungeonRenderer` — только ASCII-отрисовка;
- `AsciiRenderOptions` — параметры сетки и шрифта.
- `InventoryPanel` — подготовка, просмотр экипировки и использование расходников; Alt меняет только видимые подробности;
- `CombatPanel`/`CombatAsciiRenderer` — клавиатурный бой, журнал и декоративная сцена; `CombatAnimation` воспроизводит готовые события;
- `RewardPanel`/`RewardReveal` — только оставшиеся предметы и последовательное раскрытие уже рассчитанных свойств;
- `ItemRarityStyle` — общие цвета, названия и коды шести редкостей, включая анимированный Unique;
- `GameSettings`/`SettingsPanel` — сохранение настройки рулеток и меню; `TerminalOverlay` — общая ASCII-сетка экранов награды и настроек.

## Как расширяется мир

Мир хранит только раскрытые клетки. При открытии внешней двери `DungeonMap` вычисляет соседний сектор и просит `RegionGenerator` создать там комнату или коридор. Обе области используют одну граничную клетку двери. Если соседний сектор уже существует, создаётся соединение и петля.

Комнаты собираются из пересекающихся прямоугольных частей и могут содержать перегородки. Коридоры используют тот же интерфейс дверей, поэтому являются полноценными областями мира.

Стены не принадлежат отдельным комнатам: `DungeonGrid` вычисляет один общий контур вокруг всего раскрытого пола. При появлении нового прохода прежняя стена исчезает автоматически. Каждая дверь обязана иметь проходимые клетки по своей оси и стеновую раму поперёк неё. Внутренние перегородки создаются транзакционно: вариант принимается только тогда, когда дверь в перегородке сохраняет связность всех частей комнаты и подходов к внешним выходам.

Враги генерируются только в части новых комнат. Стартовая комната и коридоры безопасны. По умолчанию шанс заселения комнаты равен 38%, а число врагов — от 1 до 3. Они не появляются на дверях или вплотную к ним. `Enemy Room Chance` и `Maximum Enemies Per Room` доступны у узла `DungeonGame` в Inspector.

Игрок создаётся как `PlayerCharacter : Actor` на клетке `Floor` и регистрируется в том же пространственном слое, что и другие акторы. `DungeonMap` возвращает типизированные результаты движения и взаимодействия с дверью, поэтому Presentation только выбирает текст/визуализацию результата. Позиция меняется через `EntityRegistry`: успешный ход обновляет объект и индекс вместе, а отклонённый не меняет ни один из них.

Чтобы добавить новый тип врага, нужно унаследоваться от `Enemy` и добавить его создание в `EnemyFactory`. Алгоритм размещения и карта при этом не меняются.

## Проверка

`tests/PlayerCharacterSmokeTest.cs` проверяет регистрацию игрока, атомарное успешное/отклонённое перемещение, запрет команд после смерти, расчёт характеристик и инварианты текущих ресурсов при изменении максимумов. `tests/DungeonGenerationSmokeTest.cs` генерирует 100 миров по 200 областей. Для каждой открытой двери проверяется, что с обеих сторон остаются проходимые клетки. Затем BFS от точки старта проверяет потенциальную достижимость каждой раскрытой клетки пола и каждого врага; закрытые двери при этой геометрической проверке считаются открываемыми. Это защищает от дверей-тупиков, комнат-островов и перекрытия прохода поздними перегородками.

Полная проверка (путь к Godot Mono замените при другой установке):

```powershell
dotnet build .\CmdRoguelike.csproj --no-restore
if ($LASTEXITCODE -ne 0) { throw 'Сборка не прошла.' }
$taskGodot = 'D:\Godot_v4.6.2-stable_mono_win64\Godot_v4.6.2-stable_mono_win64_console.exe'
$taskTests = @(
    'campaign', 'reward', 'item_affix', 'equipment', 'preparation_ui', 'combat',
    'combat_animation', 'combat_ui', 'player_character', 'dungeon_generation'
)
foreach ($taskTest in $taskTests) {
    & $taskGodot --headless --path . --log-file ".godot/$taskTest-check.log" "res://tests/${taskTest}_smoke_test.tscn"
    if ($LASTEXITCODE -ne 0) { throw "Тест $taskTest не прошёл." }
}
& $taskGodot --headless --path . --log-file '.godot/main-check.log' --quit-after 3
if ($LASTEXITCODE -ne 0) { throw 'Основная сцена не загрузилась.' }
```

Для получения снимков запускайте соответствующие UI-сцены без `--headless`. Автоматические проверки не заменяют просмотр кадров после изменений рисунка, цвета или расположения текста. После добавления прохождений от 2026-10-10 прошли все десять smoke-сцен, сборка без ошибок и предупреждений и загрузка основной сцены. CampaignSmokeTest пройден с графикой: меню → база → экипировка → дуб → награда → портал → база, а также выход вне боя и во время боя. Просмотрены кадры базы, хранилища, энциклопедии, дуба и портала. Ранее графически проверены инвентарь с Alt и без него, палитра, оставшаяся добыча и новый силуэт защитника. Подробные инварианты и покрытие тестов перечислены в [AGENTS.md](AGENTS.md).
